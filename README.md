# AEL Round 1 kit

Builds the Round 1 scenario set: 17 situations × 3 levels = 51 scenes, 646 scenarios, in one file, `scenarios.json`.
Full instructions are in the "Scaling Scenario Generation" doc (Start here, then your own guide).
What changed since the first release, and who added it: see [CHANGELOG.md](CHANGELOG.md).

Requires Python 3.10+ and `pip install pyyaml==6.0.3 jsonschema==4.26.0`. Works on Windows, macOS and Linux;
on Windows the `cp` and `scenes/*.yaml` lines below need Git Bash.

## Build and check (2 minutes)

Run from this folder:

```
python make_scenes.py                                       # wrote 51 scene files for 17 situations
python reference_pipeline.py scenes/*.yaml --out expected   # ... wrote expected/scenarios.json with 646 scenarios
python verify_round.py expected                             # last line: ... ALL CHECKS PASS (see Known issues)
python make_catalog.py                                      # writes catalog.md
cp expected/scenarios.json ../round1_scenarios.json
```

`scenes/`, `expected/`, `catalog.md` and `../round1_scenarios.json` are generated by these steps and are not committed.
To change a situation, edit `make_scenes.py` and rebuild; never edit or commit files in `scenes/`.

The deliverable is `expected/scenarios.json`.
Each entry holds the scenario id, scene, situation, level, anchor id, changed variable, bin, every variable's value,
the narrative, the Codebook v4 record, and the U and K labels.

## Files

| Path | What it is |
| --- | --- |
| `make_scenes.py` | The situation definitions, one `SITUATIONS.append(...)` block each, in build order; writes the scene files |
| `scenes/<situation>_<level>.yaml` | The generated scene files (3 per situation) |
| `reference_pipeline.py` | Expands each scene into its anchor and twins, builds the records, labels them, writes the narratives, and merges everything into `scenarios.json` |
| `codebook/labeler.py`, `codebook/schema_scenario_v4.json` | Codebook v4's labeler and record schema |
| `verify_round.py` | Checks every scene (counts, anchor conflict, Kantian twins flip K, scenery twins change nothing) and `scenarios.json` (unique ids, schema, labels reproduced) |
| `lint.py` | Checks scene files for structural mistakes; used when writing new situations |
| `show_scenario.py` | `python show_scenario.py one_vs_five_high-S01` prints one scenario for review; `--all` with a scene id prints the whole scene |
| `reviews.py` | `python reviews.py new <name> <situation> <situation>` creates a review sheet; `python reviews.py summary` checks all sheets |
| `reviews/<reviewer>.csv` | Review sheets; `reviews/failed_items.yaml` tracks each failure by cause until it is fixed or accepted |
| `reviews/claude_assisted/` | A Claude-assisted review of brake_failure_van and truck_shield, with a readable copy of those scenarios |
| `make_catalog.py`, `catalog.md` | The scene catalog |
| `expected/` | The build output: `scenarios.json`, `ALL_expected_labels.csv`, and one folder per scene |

The per-scene folders also contain `packets/` and `key.csv`, prompt files for a later model round. This round does not use them.

## Known issues

- `verify_round.py` fails on **duplicate case codes**: `GKG`, `FQU`, `CRN`, `X8K`, `UJF`, `8TA`, `ANN`.
  Each scene draws its 3-character codes from its own seed, so codes can repeat across scenes; every other check passes.
  Case codes only matter for the packets, which this round does not use.
- **Reviews cover the first 6 situations only** (228 of 646 scenarios). Situations 7-17 have no review sheets yet.
